# Кнопка → LoRa → світлодіод (Heltec WiFi LoRa 32 V4.3)

Проєкт для **двох однакових плат Heltec WiFi LoRa 32 V4.3 з радіомодулем 868 МГц**. Плата A зчитує двоконтактну кнопку, плата B вмикає зовнішній світлодіод, поки кнопка натиснута. Білий світлодіод на платі B також показує цей стан.

## Підключення

| Плата | Підключення |
| --- | --- |
| A, кнопка або двоконтактний вимикач | Один контакт до **GPIO4** (пін `4`), другий до **GND** |
| B, зовнішній світлодіод | **GPIO4** → **резистор 330 Ω** → **анод LED (+, довга ніжка)**; **катод LED (−, коротка ніжка)** → **GND** |

Для кнопки окремий резистор не потрібен: GPIO4 працює як `INPUT_PULLUP`. Замкнена кнопка дає стан «увімкнено». Якщо це кнопка без фіксації, світлодіод горить тільки під час натискання. Якщо це двоконтактний вимикач з фіксацією, світлодіод повторює його положення.

Не з'єднуйте кнопку з 3V3/5V. Світлодіод підключайте **тільки через резистор** (підійде приблизно 220–1000 Ω). Якщо він не світить, перевірте полярність. Вбудований білий LED на платі B уже підключений до GPIO35 і зовнішніх проводів не потребує. GPIO4 плати A та GPIO4 плати B — виводи **різних** плат; дріт між платами не потрібен.

GPIO4 вибрано за [офіційною схемою V4.3](https://resource.heltec.cn/download/WiFi_LoRa_32_V4/Schematic/HTIT-WB32LAF_V4.3.pdf) та [схемою виводів Heltec](https://resource.heltec.cn/download/WiFi_LoRa_32_V4/Pinmap/V4_pinmap.png). Цей проєкт розрахований на V4.3, не на V4-R8 чи V3.

## Прошивання

1. Під'єднайте антени 868 МГц до обох плат **перед передаванням**.
2. Відкрийте каталог у VS Code з PlatformIO. Дізнайтеся актуальні USB-порти командою `& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device list` у PowerShell.
3. Прошийте плату з кнопкою середовищем `node_a`, плату зі світлодіодом — `node_b`. Замініть `COM5` і `COM6` на свої порти:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e node_a -t upload --upload-port COM5
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -e node_b -t upload --upload-port COM6
```

Для перевірки відкрийте монітори зі швидкістю 115200 бод:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device monitor -p COM5 -b 115200
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" device monitor -p COM6 -b 115200
```

На дисплеї A видно стан кнопки та підтвердження зв'язку; на дисплеї B — стан LED. Після запуску A одразу надсилає поточний стан. Далі надсилає при зміні та повторює стан кожні 15 секунд. B підтверджує отримання; за відсутності пакетів 45 секунд вона вимикає LED. Після відновлення зв'язку стан синхронізується знову. Коротке натискання менше ніж 120 мс відкидається як брязкіт контактів.

## Налаштування і примітки

- Частота `868.0` МГц задається в [src/main.cpp](src/main.cpp); обидві плати мають використовувати однакову частоту й відповідні антени. Перевірте відповідність частоти та режиму передавання правилам вашого місця використання.
- `PIN_BUTTON` і `PIN_EXTERNAL_LED` зараз дорівнюють GPIO4. Якщо згодом підключите до інших вільних GPIO, змініть ці константи в коді й перепрошийте відповідні плати.
- `heltec_wifi_lora_32_V3` у `platformio.ini` використовується тільки як ціль компіляції ESP32-S3. Піни радіо, підсилювача й OLED налаштовані в коді саме для V4.3.
- На платах V4-R8 відрізняються, зокрема, GPIO живлення OLED та вбудованого LED. Цей код для них не підходить без змін.
- Якщо ініціалізація LoRa завершується помилкою, перевірте маркування V4.3 і підключення антени. Якщо пакети не приймаються, спробуйте рознести плати на кілька метрів: дуже близькі передавач і приймач можуть перевантажувати радіотракт.
